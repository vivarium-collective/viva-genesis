# Narrative-field redundancy review — origins-of-life-vent

How the `investigation.yaml` / `study.yaml` narrative fields come together with
the vivarium-workbench renderers, where they duplicate each other, and how to cut
the total authored text while keeping the investigation more precise. Grounded in
a field→view audit of the renderers (not a guess).

## Method

Every narrative field was mapped to its consumer(s) across the renderers:

- **IR** — `templates/investigation-report.html` (exported investigation report)
- **W** — `static/walkthrough.js` (live SPA investigation page)
- **SD** — `templates/study-detail.html` (live study-detail tabs)
- **SSR** — `lib/single_study_report.py` (exported single-study report)
- **WJ** — `walkthrough.js` study cards in the SPA

## Headline findings

1. **Some authored fields render nowhere.** A repo-wide grep found zero renderer
   consumers for `executive.architecture_thesis`, `scientific_argument.{emergence_criterion,
   model_structure_vs_parameters, endpoint}` (ad-hoc), and — importantly —
   `executive.verdict_detail` and `at_a_glance[]` (which are *scaffolded* yet still
   unrendered; the on-screen "At a glance" table is computed from the studies via a
   `roleLine()` helper, not from the field). Authors fill these every time; no view
   shows them.

2. **The per-study `report.*` block is a second renderer's private copy.** SD (live)
   and SSR (export) diverged and read *different keys for the same UI slot*:

   | UI slot | SD reads | SSR reads |
   |---|---|---|
   | verdict | computed from `gate_status` | `report.verdict` |
   | confidence | `study.confidence` | `report.confidence` |
   | result | `result` | `report.result` / `report.main_insight` |
   | conclusion | `conclusion` | `report.conclusion` |
   | caveat | `limitations[0]` | `report.caveat` |

   So the whole `report.*` prose block duplicates the top-level/computed fields — a
   *two-renderers* problem, not a content one.

3. **Numbers are retyped as prose in 5+ fields.** The gate results (e.g. og-00's
   50.6 °C / pH 9.37 / 80%) live in `claim`, `result`, `findings[].evidence`,
   `report.key_metrics`, `conclusion`. Retyping is the source of the real drift bugs
   hit during the narrative pass (og-02 "~3 vs 29.5", og-03 "1e6–1e7 vs 9.6e7").

4. **Per-study headline is re-authored 8–10×.** `claim` / `result` /
   `findings[].statement` / `report.main_insight` / `report.conclusion` /
   `conclusion` / `conclusion_verdicts.*.basis` / `resolved_uncertainties` are
   paraphrases of one story.

## Recommendations — three tiers, smallest-risk first

### A. Delete the ad-hoc unrendered fields (instance-level, free) — DONE in PR #38
`architecture_thesis`, `emergence_criterion`, `model_structure_vs_parameters`,
`endpoint`: unrendered, no consumers, substance single-sourced in
`guidelines.architecture_principles` + the `lead`. No workbench change.

### B. Fix the scaffolded-but-dead fields at the schema level (not per-instance)
`executive.verdict_detail` is generated by the viva-investigation skill
(`scaffold.py:784`) but rendered by nothing — every investigation author fills a
dead field. Fix in **viva-template scaffold + the skill** (stop scaffolding it, or
wire a renderer), not by deleting it from one workspace. Same question for
`at_a_glance[]` (scaffold/payload vs the computed table).

### C. Collapse the per-study `report.*` block into the top-level fields
Repoint SSR (`single_study_report.py`) to read `claim` / `limitations[0]` /
`study.confidence` / computed-verdict / top-level `key_metrics` — the keys SD
already uses — and drop the `report.*` prose block from every study. Pair with
**numbers-as-data**: `key_metrics` becomes the single home for the figures; `claim`
and `result` stop embedding them (SD/SSR render the metric table in the Result
slot). This is the fix that structurally prevents the number-drift bugs.

**Worked example:** PR #40 (draft) rewrites og-00 under this collapsed schema with
the exact workbench render-diff in `PROTO_NOTES.md` — authored narrative fields
~13 → ~6, every number sourced once, no view loses content. Not mergeable until the
render-diff + a one-time 16-study migration land together.

## For genesis-viz
The field→view table above is the canonical map for keeping figure captions in sync
with the fields a given view actually reads (e.g. SSR headline ← `claim`, not
`report.main_insight`; Result ← `key_metrics`). Caption language should follow the
*kept* field in each slot once tier C lands.
